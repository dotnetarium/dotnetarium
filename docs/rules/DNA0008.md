# DNA0008: Risky Json.NET polymorphism setting

Json.NET can read type names from JSON when `TypeNameHandling` is enabled. If untrusted input is allowed to select unexpected .NET types, deserialization may invoke behavior that the application did not intend to expose.

The rule reports a constant non-`None` setting. It does not establish that the settings are later used with untrusted JSON, so review the deserialization call and its input before assessing exposure.

## Recommendation

Leave `TypeNameHandling` set to `None` when reading untrusted JSON. If polymorphism is necessary, restrict the permitted types with a reviewed serialization binder rather than accepting arbitrary type names.

## Example

Do not enable type selection for an ordinary request model:

```csharp
var settings = new JsonSerializerSettings {
    TypeNameHandling = TypeNameHandling.None
};
var request = JsonConvert.DeserializeObject<OrderRequest>(json, settings);
```

Ordinary `System.Text.Json` deserialization is not reported by this rule.
