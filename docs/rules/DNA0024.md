# DNA0024: Unrestricted credentialed CORS

An applied ASP.NET Core CORS policy accepts every origin and allows credentials.
Restrict origins to sites you control and trust for authenticated access.

```csharp
options.AddPolicy("trusted", policy => policy
    .WithOrigins("https://app.example.com")
    .AllowCredentials());
```

The rule recognizes constant-true `SetIsOriginAllowed` predicates, including
simple source helpers returning `true`, combined with `AllowCredentials` on the
same builder. Named policies must be applied with `UseCors`, `RequireCors` or
`EnableCors`; applied default and inline policies are also supported.

Public APIs using `AllowAnyOrigin` without credentials, unused named policies,
credential settings subsequently disabled, and restricted origin predicates
are excluded. The framework rejects `AllowAnyOrigin` combined with credentials;
this rule targets the custom-predicate bypass that accepts and reflects origins.

The diagnostic establishes unsafe configuration, not proven account compromise.
Impact depends on browser credentials, cookie policy and the resources served.
Conditional configuration, aliases and duplicate policy registrations are not
resolved by the initial implementation.

Reference: [ASP.NET Core CORS](https://learn.microsoft.com/aspnet/core/security/cors).
