# DNA0020: TLS certificate validation bypass

TLS certificate validation establishes that a connection is made to the intended peer. A callback that accepts every certificate removes that authentication. An attacker able to intercept the connection may impersonate the service even though the traffic still uses HTTPS.

## Recommendation

Remove the accept-all callback and retain the platform's certificate validation. For development, trust the appropriate development certificate in the client's trust store. If custom validation is necessary, verify the certificate and intended identity rather than returning a constant result.

## Example

This configuration accepts an invalid or unrelated server certificate:

```csharp
handler.ServerCertificateCustomValidationCallback =
    HttpClientHandler.DangerousAcceptAnyServerCertificateValidator;
```

For normal HTTPS requests, omit that assignment and let `HttpClientHandler` validate the certificate.

The rule checks installed callbacks that are proven to accept every certificate. Recognized development/non-production guards, DEBUG-only code and test projects are excluded to reduce noise. Those exclusions do not establish that a deployed bypass is safe, and a custom validator left unreported may still be incorrect.
