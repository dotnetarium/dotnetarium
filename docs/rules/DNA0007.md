# DNA0007: XPath injection

An XPath expression built from user input can select a different part of an XML document than intended. For example, an attacker may alter a search predicate to read other records or bypass an application check based on the query result.

## Recommendation

Keep user values separate from XPath syntax. Use XPath variables when the query API supports them. If the application offers only a few query choices, map those choices to fixed expressions.

For example, concatenating a name into `"/users/user[name='" + name + "']"` lets a quote in `name` alter the predicate. A variable such as `$name` avoids that problem only when it is bound as a value through the XPath context; replacing the variable text with string substitution does not.

Do not use XML or HTML encoding as an XPath escaping mechanism. Encoding XML markup does not account for the expression's grammar.
