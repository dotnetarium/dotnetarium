# DNA0024: Unrestricted credentialed CORS

A CORS policy that accepts every origin and allows credentials can let an untrusted website read authenticated responses from the application. Exposure depends on whether the browser sends usable credentials and whether the response contains sensitive information.

ASP.NET Core rejects `AllowAnyOrigin` combined with credentials. An always-true `SetIsOriginAllowed` predicate can bypass that restriction by accepting and reflecting each requesting origin.

## Recommendation

List the specific origins trusted to access authenticated responses. Enable credentials only when the application requires them; a public unauthenticated API has different requirements.

## Example

Use an explicit origin instead of an accept-all predicate:

```csharp
options.AddPolicy("frontend", policy => policy
    .WithOrigins("https://app.example.com")
    .AllowCredentials());
```

The rule requires the unsafe policy to be applied, for example through `UseCors`, `RequireCors` or `EnableCors`. Unused named policies and policies without credentials are excluded. A finding establishes the configuration problem, not that a browser-based attack has been demonstrated.
