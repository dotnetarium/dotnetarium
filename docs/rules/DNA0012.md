# DNA0012: Dynamic code execution

Compiling or evaluating user-supplied code gives that input the capabilities of the execution environment. If the application runs it in its own process, the code may access application data, credentials and operating-system resources with that process's permissions.

## Recommendation

Avoid accepting executable code for features that only need data or a limited expression. Use a parser with a small, explicit set of permitted operations instead. Removing a few dangerous words or namespaces does not create a reliable execution boundary.

For example, passing a request value to a C# scripting evaluation API permits much more than arithmetic. A calculator feature should parse its supported operators and values rather than execute arbitrary C#.

The rule follows untrusted input into supported compilation and evaluation APIs. Review whether the feature intentionally executes code and what isolation exists outside the analyzed process; the rule does not establish that such isolation is present.
