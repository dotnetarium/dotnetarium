# DNA0009: Hard-coded secrets in code

A password or encryption key embedded in source code can be recovered from the repository or distributed application. Sharing the same value between installations also makes rotation harder and increases the impact of a disclosure.

This rule looks at how a literal is used, such as a password passed to `NetworkCredential` or key bytes supplied to a cryptographic API. A variable name that merely contains `password` or `secret` is not enough.

## Recommendation

Retrieve production credentials from a managed secret store or deployment configuration. Replace credentials that may have been exposed; removing them from the current source file does not revoke existing copies.

## Example

Replace an embedded password:

```csharp
var credential = new NetworkCredential("service-user", "fixed-password");
```

Supply the secret through deployment configuration instead:

```csharp
var credential = new NetworkCredential(
    configuration["Service:User"], configuration["Service:Password"]);
```

That configuration must itself be supplied securely. Deliberate cryptographic test vectors may need a targeted suppression. Configuration-file provider tokens are handled separately by DNA0022.
