# DNA0019: gRPC call credentials over plaintext

gRPC call credentials commonly carry authentication tokens or other credentials in request metadata. Sending them over plaintext HTTP allows an observer on the network path to read or modify that traffic.

The client normally restricts call credentials on insecure channels. Explicitly enabling `UnsafeUseInsecureChannelCallCredentials` removes that protection.

## Recommendation

Use an HTTPS destination with normal certificate validation for authenticated calls. Do not enable insecure call credentials to work around a TLS configuration problem; correct certificate trust or the service endpoint instead.

The rule requires a constant remote `http://` address, inline channel options, the insecure-credential opt-in and supplied call credentials in `GrpcChannel.ForAddress`. Loopback destinations are excluded for local development. Runtime addresses and options held in variables are not inferred, so the absence of this diagnostic is not evidence that every channel uses TLS.
