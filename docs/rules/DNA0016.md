# DNA0016: Low PBKDF2 work factor

PBKDF2 deliberately repeats a derivation operation to make password guessing more expensive. A low iteration count reduces that cost for an attacker who obtains password hashes or other data that allows guesses to be checked offline.

The rule reports explicit constant counts below 100,000 in supported .NET and ASP.NET Core APIs, including `PasswordHasherOptions.IterationCount`. That threshold identifies weak settings; it is not a recommendation that 100,000 iterations is sufficient.

## Recommendation

Choose the work factor for the hash algorithm and deployment, using current password-storage guidance and measurements on the systems that perform verification. Increase the cost as part of a versioned password-hashing scheme so existing passwords can be rehashed after successful authentication.

For ASP.NET Core Identity, prefer its password hasher and a deliberate configuration over a separate password format assembled from low-level cryptographic calls. A variable iteration count is not evaluated by this rule, so review configuration supplied at runtime as well.
