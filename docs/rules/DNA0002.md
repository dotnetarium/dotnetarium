# DNA0002: OS command injection

A process started with user-controlled command text may run a different program or perform additional operations. The risk depends on both the executable and the arguments it accepts. Shells are particularly dangerous because their input is another command language.

## Recommendation

Use a library API instead of launching a process when possible. Otherwise, choose a fixed executable and validate arguments according to that program's interface. Pass individual arguments through `ArgumentList` rather than constructing an `Arguments` string.

`ArgumentList` handles argument boundaries; it does not make arbitrary options or shell scripts safe. Do not pass untrusted script text to commands such as `sh -c` or `cmd /c`.

## Example

For a utility that supports `--` as an end-of-options marker, keep the executable and options fixed:

```csharp
var start = new ProcessStartInfo("/usr/bin/sha256sum") {
    UseShellExecute = false
};
start.ArgumentList.Add("--");
start.ArgumentList.Add(validatedFilePath);
Process.Start(start);
```

The path still needs its own access restrictions. This rule reports supported executable-name and command-string sinks; it does not analyze `ArgumentList` contents or prove that a shell is involved.
