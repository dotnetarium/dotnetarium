# DNA0018: Detailed gRPC errors enabled

Detailed gRPC errors can send exception information back to a client. Details that help during development may disclose implementation information or application data when an error occurs in a deployed service.

## Recommendation

Leave detailed errors disabled in production. Return controlled gRPC status information to clients and record the full exception in server-side logs with appropriate access controls.

## Example

Limit detailed errors to the framework's development environment:

```csharp
builder.Services.AddGrpc(options => {
    options.EnableDetailedErrors = builder.Environment.IsDevelopment();
});
```

This rule reports unconditional `EnableDetailedErrors = true` service registrations. It skips conditionally guarded registrations and does not evaluate runtime configuration providers. A skipped condition is not proof that a deployment disables detailed errors; check the effective service configuration when reviewing exposure.
