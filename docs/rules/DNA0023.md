# DNA0023: Unsafe BinaryFormatter deserialization

`BinaryFormatter` can instantiate objects with dangerous behavior while deserializing data. An attacker who controls its input may be able to execute code in the application process. A serialization binder is not a reliable way to make this format safe for untrusted input.

The in-box .NET 10 implementation throws instead of deserializing. The unsupported compatibility package restores the old implementation and its risks. This rule requires an explicit reference to that package and untrusted byte or stream input reaching `Deserialize`.

## Recommendation

Replace the format with a serializer such as `System.Text.Json` and an application-defined data schema. Plan migration of existing stored data rather than accepting an unsafe format on an exposed request path. Do not restore BinaryFormatter merely to make old deserialization code run on a new framework.

Enabling an old project flag alone does not trigger this rule. A fixed payload is also not reported merely because the API appears in the code.
