# DNA0022: Hard-coded network credentials

A provider token or authentication key in a configuration file can give anyone with access to that file the ability to authenticate to the provider. Committing it to a repository may expose it through history, forks, build artifacts or copied configuration, even after the current value is removed.

This rule recognizes selected provider credential formats, including GitHub, AWS, Azure, Google Cloud and infrastructure services. It does not need to find a C# call that uses the credential. Public identifiers such as account IDs and client IDs are excluded.

## Recommendation

Remove the credential from the file and supply it through a secret store or the deployment platform's secret mechanism. Revoke or rotate credentials that may have been exposed. Replacing a committed credential with a secret reference does not invalidate the old value.

## Example

A GitHub Actions workflow should reference a secret instead of containing a token value:

```yaml
env:
  GH_TOKEN: ${{ secrets.SERVICE_TOKEN }}
```

Detection is offline by default. A format match does not establish that the credential is active. The CLI can optionally verify supported credentials; verification results do not remove the finding.
