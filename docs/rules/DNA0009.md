# DNA0009: Hard-coded secrets in code

CWE-798. Reports C# code that passes a literal password or cryptographic key to a security-sensitive API, such as `new NetworkCredential("user", "password")` or an encryption API using a fixed key. A suspicious variable name alone is not enough. Load production secrets from a managed secret store or deployment configuration. The rule skips obvious template markers such as `YOUR_PASSWORD_HERE`, but cannot tell whether every other literal is a real production secret. Review test vectors in their deployment context.

This rule reports a candidate that needs review in the application's trust context. Configure severity with `dotnet_diagnostic.DNA0009.severity` in `.editorconfig`.

Built-in key sinks include .NET symmetric and AEAD APIs, Bouncy Castle `KeyParameter`, NSec `Key.Import` / `TryImport`, and Sodium.Core `SecretBox` and `SecretAead*` encryption and decryption methods. Literal byte arrays and inline zero-filled key arrays are reported; a key produced by a generator is not.

## Difference from network credential detection

This rule checks **how a literal secret is used in C# code**. It can report an ordinary password without any provider-specific token format.

[DNA0022: Hard-coded network credentials](DNA0022.md) checks **configuration-file contents** for recognizable provider tokens and authentication keys. It does not require an API call or proof that the application uses the credential.
