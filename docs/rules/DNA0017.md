# DNA0017: Hardcoded post-quantum private key

A private key embedded in application code can be recovered from the source or distributed binary. Using a post-quantum algorithm does not protect a private key that is already known to an attacker.

The rule checks literal private-key imports through the .NET 10 `MLKem`, `MLDsa` and `SlhDsa` APIs, including supported PEM imports. Public keys are intended to be distributed and are not reported by this rule.

## Recommendation

Generate private keys securely and keep persisted keys in protected storage with access limited to the service that needs them. Load them at runtime through the application's key-management mechanism. Replace any key that may have been exposed and update dependent public-key registrations or trust configuration as required.

Published test vectors can legitimately contain fixed private keys. Keep those fixtures separate from production key loading and suppress only the deliberate fixture.

This rule checks embedded key material. It does not assess PQC parameter choices or establish that a key loaded from runtime configuration is protected.
