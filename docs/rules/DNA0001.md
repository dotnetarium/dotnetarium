# DNA0001: SQL injection

When user input becomes part of SQL command text, the database can interpret it as query syntax rather than data. An attacker may be able to read or change records that the application did not intend to expose.

## Recommendation

Keep the SQL statement separate from its values by using the database API's parameters. This applies to raw SQL in EF Core and to libraries such as Dapper as well as direct database commands. Parameters cannot represent table names, column names or sort directions; select those from a fixed set of permitted choices.

## Example

In this Dapper query, a quote in `name` can change the SQL statement:

```csharp
connection.Query<User>(
    "SELECT Id FROM Users WHERE Name = '" + name + "'");
```

Pass the value separately instead:

```csharp
connection.Query<User>(
    "SELECT Id FROM Users WHERE Name = @name", new { name });
```

The rule checks SQL text supplied to supported database APIs. Supplying an untrusted value as a database parameter does not make that parameter a SQL-text sink.
