# DNA0015: Fixed encryption IV or nonce

An IV or nonce is part of an encryption scheme's security requirements, not a second secret key. A fixed value can cause relationships between messages to become visible. For authenticated encryption such as AES-GCM, repeating a nonce with the same key can also allow forgery.

## Recommendation

Use an unpredictable IV for CBC and a nonce that is unique for each encryption under the same key for AEAD schemes. Follow the selected algorithm's size and usage limits. Store the IV or nonce with the ciphertext so the receiver can decrypt it.

## Example

For AES-GCM, generate a nonce for each message rather than using a zero-filled array:

```csharp
byte[] nonce = RandomNumberGenerator.GetBytes(12);
using var aes = new AesGcm(key, tagSizeInBytes: 16);
aes.Encrypt(nonce, plaintext, ciphertext, tag);
```

Keep `nonce` and `tag` with the resulting ciphertext. The rule detects fixed material at supported encryption calls, including simple unchanged local values. It does not prove nonce reuse across fields, processes or separate calls, and it does not report decryption.
