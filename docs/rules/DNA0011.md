# DNA0011: Server-side request forgery

When a caller controls an outbound request destination, the application may become a way to contact internal services or other destinations the caller cannot reach directly. Responses may expose data, and requests may trigger operations under the server's network identity.

## Recommendation

Prefer fixed destinations or select them from a trusted allowlist. Restrict schemes, hosts and permitted network addresses, and apply the policy to redirects as well as the initial request.

A fixed `HttpClient.BaseAddress` is not enough if the supplied request URI can be absolute. An absolute URI can replace the base address rather than append a path to it. For a request intended for one service, accept a constrained identifier or path instead of an arbitrary URL.

The rule follows supported HTTP and gRPC destinations, including tracked `BaseAddress` and `RequestUri` assignments. Server-side Blazor navigation URLs can also be influenced by request host information. Some URI and channel construction sites are reported before a request is proven to occur; check the consuming operation when reviewing those findings.
